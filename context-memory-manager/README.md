# إدارة السياق والذاكرة للمشاريع (Context & Memory Manager)

إضافة متقدمة لبيئة **Antigravity** تمنح الوكيل الذكي (Agent) ذاكرة مستمرة واعية بهيكل ومشاريع بيئة العمل الخاصة بك.

عند بدء كل جلسة عمل، تقوم الإضافة تلقائياً بفحص ملفات السياق والمعمارية في مجلد المشروع وحقنها في ذاكرة الوكيل، مما يلغي الحاجة إلى إعادة شرح تفاصيل المشروع في كل محادثة جديدة.

---

## 🌟 الميزات الرئيسية

1. **التحميل التلقائي للسياق (Session Start Hook)**:
   - عند تشغيل الجلسة، يقوم خطاف Node.js بفحص مساحة العمل المفتوحة والبحث عن ملفات التوثيق والمعمارية الأساسية.
   - يتم تحميل المحتوى فوراً كرسالة سياقية مؤقتة (Ephemeral Context) تتيح للوكيل استيعاب التقنيات والأنماط المتبعة.

2. **مهارة تحليل مساحة العمل (`workspace-analyzer`)**:
   - استكشاف هيكل المشروع واللغات وأطر العمل والتبعيات والأنماط المعمارية.
   - إنشاء أو تحديث ملف `PROJECT_CONTEXT.md` في جذر المشروع ليصبح مرجعاً دائماً.

3. **مهارة بناء قاعدة المعرفة (`knowledge-base-builder`)**:
   - توثيق سجلات القرارات المعمارية (Architectural Decision Records - ADRs).
   - إعداد كتيبات التشغيل وإجراءات العمل (Runbooks).
   - توثيق اتفاقيات كتابة الكود والتسمية والعمليات البرمجية (`CONVENTIONS.md`).

4. **قواعد سلوك صارمة (`AGENTS.md`)**:
   - إجبار الوكيل على مراجعة ملفات الذاكرة قبل اتخاذ أي قرار برمجي أو معماري.
   - الحفاظ على التناسق المعماري ومنع كسر القرارات السابقة.
   - اقتراح تحديث ملفات التوثيق بشكل استباقي عند إدخال تقنيات أو أنماط جديدة.

---

## 📁 الملفات التي تفحصها الإضافة تلقائياً

يبحث خطاف `hooks/load-context.js` عن الملفات التالية بترتيب الأولوية في جذر المشروع والمجلدات الفرعية الشائعة:

| اسم الملف | الوصف والغرض |
| :--- | :--- |
| `PROJECT_CONTEXT.md` | الملف الرئيسي لذاكرة المشروع (الهيكل، التقنيات، الأنماط، المهام الحالية). |
| `ARCHITECTURE.md` | التوثيق المعماري وتصميم النظام والخدمات. |
| `ADR.md` | ملخص أو سجل القرارات المعمارية الرئيسية. |
| `.agents/PROJECT_CONTEXT.md` | ملف سياق خاص بوكلاء الذكاء الاصطناعي. |
| `docs/ARCHITECTURE.md` | وثائق المعمارية داخل مجلد المستندات. |
| `CONTEXT.md` | ملف السياق العام للمشروع. |

## 🚀 كيفية الاستخدام

### 1. تحليل مشروع جديد وإنشاء ملف الذاكرة
إذا كنت تفتح مشروعاً جديداً أو غير موثق، يمكنك ببساطة توجيه أحد الأوامر التالية للوكيل:
- `"حلل مشروعي وأنشئ ملف PROJECT_CONTEXT.md"`
- `"Analyze my workspace and build a PROJECT_CONTEXT.md memory file"`
- `"تعرف على هذا المشروع واحفظ بنيته في الذاكرة"`

سيقوم الوكيل بتشغيل مهارة `workspace-analyzer` لفحص الملفات وإنشاء المستند النموذجي.

### 2. توثيق قرار معماري (ADR)
عند اتخاذ قرار تقني هام (مثل اختيار مكتبة مصادقة أو تبديل قاعدة بيانات):
- `"وثق قرار التحول إلى PostgreSQL في ADR جديد"`
- `"Create an ADR for our new authentication strategy"`

يقوم الوكيل بتوليد ملف قرار رسمي في `docs/adr/ADR-NNN-title.md` وفق النموذج القياسي.

### 3. إعداد دليل تشغيلي (Runbook)
- `"اكتب Runbook لعملية النشر اليدوي للإنتاج"`
- `"Create a runbook for database migrations and rollbacks"`

### 4. استرجاع معلومات المشروع من الذاكرة
- `"ماذا تعرف عن مشروعي من الذاكرة؟"`
- `"Show me what you know about my current project from memory"`

## 📂 بنية الإضافة (Directory Structure)

```
context-memory-manager/
├── plugin.json                              # بيانات تعريف الإضافة والأوامر المقترحة
├── hooks.json                               # ربط خطاف بدء الجلسة SessionStart
├── README.md                                # التوثيق الشامل للإضافة باللغة العربية
├── hooks/
│   └── load-context.js                      # سكربت فحص وحقن ملفات السياق تلقائياً
├── rules/
│   └── AGENTS.md                            # القواعد الإلزامية للوكيل بخصوص الذاكرة
└── skills/
    ├── workspace-analyzer/
    │   └── SKILL.md                         # مهارة فحص وتحليل المشروع
    └── knowledge-base-builder/
        └── SKILL.md                         # مهارة إنشاء وإدارة التوثيق وADRs
```
