# Workspace Analyzer

This skill systematically explores a project workspace and creates a persistent memory file that future sessions can load automatically.

## When to Activate
- User says "analyze my project", "what is this codebase?", "remember this project"
- Starting work on an unfamiliar repository
- After major architectural changes that should be persisted

## Step-by-Step Workflow

### Step 1: Discover Project Type
- Check for `package.json` → Node.js / JavaScript / TypeScript
- Check for `pubspec.yaml` → Flutter / Dart
- Check for `pyproject.toml` / `setup.py` / `requirements.txt` → Python
- Check for `go.mod` → Go
- Check for `Cargo.toml` → Rust
- Check for `pom.xml` / `build.gradle` → Java / Kotlin
- Check for `*.csproj` / `*.sln` → .NET / C#

### Step 2: Map Directory Structure
- Run `view_file` on root to list top-level folders
- Identify: `src/`, `lib/`, `tests/`, `docs/`, `scripts/`, `infra/`, `packages/`
- Understand monorepo vs single-project structure

### Step 3: Extract Key Information
- **Entry points**: `main.ts`, `index.js`, `app.py`, `main.go`, etc.
- **Configuration**: `.env.example`, `config/`, `settings.py`
- **Dependencies**: Read the manifest file for production + dev dependencies
- **Scripts**: Examine `scripts` section in `package.json` or `Makefile`

### Step 4: Identify Architectural Patterns
- MVC, Clean Architecture, Hexagonal, Layered, Microservices, Monolith
- State management (Redux, MobX, Riverpod, Zustand, BLoC)
- API style (REST, GraphQL, gRPC, tRPC)
- Database access pattern (ORM, Repository, Query Builder, Raw SQL)

### Step 5: Generate PROJECT_CONTEXT.md
